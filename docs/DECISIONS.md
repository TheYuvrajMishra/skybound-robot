# DECISIONS

- Repo: user supplied https://github.com/TheYuvrajMishra/skybound-robot (created 2026-10-30, empty, public). Used instead of spec name `skybound-robot-runway` and instead of private, because the user created/supplied this repo and the GitHub connector returned 403 on `create_repository` (App cannot create repos under this installation). Nothing was overwritten; the repo was empty.
- Push route: plain `git push` has no credentials in this VM (same as prior projects). Local git history, branches and tags are real; remote sync uses the GitHub connector snapshot route (`push_files`), which lands as one snapshot commit per push. That is a connector limitation, not a history rewrite of the local repo.
- Branch model in local repo: work on `dev`, merge to `main` with merge commits, no force-push. Remote snapshot goes to `main` because the connector cannot push `dev` branches/tags in this environment; tags are kept locally and listed in ROLLBACK.md.
- Gate semantics: additive (default in spec §4.4 option a). Gate value N adds N robots, capped at 40, excess converts to +10 score each and shows MAX.
- Gate interaction: both — bullets diverted (20% of volley, at least 1 when squad >= 2 and a gate/boulder is ahead) charge a gate +1 per hit up to 99, AND the gate applies when its Z reaches the squad line. Documented here per spec §4.4.
- Boulder aim assist: same diverted bullets as gates, alternating gate/boulder. Rocket AoE damages enemies and also applies to the boulder hit (single-target damage path).
- Weapon tier order: pistol (0) < minigun (1) < rocket launcher (2) < targeting rifle (3). Higher tier replaces; same/lower tier grants a fire-rate bonus level up to 3 (8% each, floor 0.7x interval).
- Contact loss: squad count only; the enemy is removed. Conceptually the rear-most robot is lost (formation slot order is deterministic, slot 0 front-centre). Invulnerability 0.8s after a loss; enemies contacting during invulnerability are removed without further loss.
- Rendering: main game uses imperative Three.js inside a React mount (R3F/Drei are used for /dev/models and /dev/anims) for pooling and fixed-timestep control. Sim never imports three.js. Render uses sim positions each frame after fixed 60Hz steps; that is the interpolation approximation, noted in PROGRESS.md.
- Palette/mood: reference sheets supplied in this chat (robot, imp, golem, weapons, gate, boulder, road, sky-city) were used as visual guidance only: white/silver hero armour, steel-grey stone, cyan hero glow, orange-red enemy glow.
- Quality: shadows only from the directional light, shadow map capped at 1024, pixel ratio capped at 2.
